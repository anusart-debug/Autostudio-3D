# AUTOSTUDIO 3D

เครื่องมือภายในของ Plan B Media — เขียนคำสั่งสร้างภาพโฆษณา OOH + แผนที่เส้นทางรถเมล์ + ใบนำเสนอฝ่ายขาย
ตอนนี้มีสองรูปแบบจากซอร์สเดียวกัน (v41 เฟส 5):

1. **ไฟล์ออฟไลน์** `dist/autostudio3d.html` — ไฟล์เดียว ดับเบิลคลิกเปิดจาก `file://` ได้เลย
   ไม่มี Google sign-in ไม่มี Drive ไม่มี API key เหมือนเดิมทุกประการ
2. **เว็บแอพ** `dist/web/index.html` — ไว้ขึ้น Firebase Hosting มี Google sign-in + บันทึกลง
   Google Drive (เฟส 6-7) ยังใช้ตัววาดคำสั่ง/แผนที่ชุดเดียวกันกับไฟล์ออฟไลน์ทุกอย่าง

**หลักการ "ตัดออก ไม่ใช่ใส่ flag":** โมดูล JS ที่ใช้เฉพาะเว็บใช้นามสกุล `.web.js` แล้ว
`build.mjs` กรองออกตอนสร้างไฟล์ออฟไลน์จริงๆ — ไม่ใช่ซ่อนด้วย `if`
ไฟล์ออฟไลน์จึง**ไม่มีสตริงเกี่ยวกับ Google sign-in/Drive อยู่จริง** พิสูจน์ได้ด้วย grep
(ดู `test/07-network.test.js`) และถ้าโมดูลเว็บพัง ก็ทำลายได้แค่ไฟล์เว็บ ไม่กระทบไฟล์ออฟไลน์

## เริ่มต้น

```bash
npm install          # ต้องใช้แค่ตอนรันเทสต์ ตัวแอปไม่มี dependency
npm run build        # → dist/autostudio3d.html + dist/web/index.html + firebase.json
npm run build:file   # เฉพาะไฟล์ออฟไลน์
npm run build:web    # เฉพาะไฟล์เว็บ (สร้าง firebase.json ให้ด้วย)
npm run check        # ตรวจว่า dist ตรงกับซอร์สทุกไบต์ทั้งสองไฟล์ ไม่เขียนทับ
npm test             # build แล้วรันเทสต์ทั้งชุด
npm run open         # build แล้วเปิดไฟล์ออฟไลน์ในเบราว์เซอร์
```

ผลลัพธ์คือไฟล์ **`dist/autostudio3d.html`** ส่งให้ฝ่ายขายดับเบิลคลิกเปิดได้เลย ไม่ต้องติดตั้งอะไร
ไม่ต้องมีเซิร์ฟเวอร์ — ขั้นตอนขึ้นเว็บแอพ (Firebase + Google sign-in + Drive) จะเพิ่มเอกสารแยก
ตอนเฟส 6-7 ทำเสร็จ

## ทำไมถึงเป็นไฟล์เดียว

ผู้ใช้ปลายทางคือฝ่ายขายที่เปิดไฟล์จากเครื่องตัวเอง (`file://`) ข้อจำกัดนี้ตัดสินสถาปัตยกรรมทั้งหมด

| ข้อจำกัด | ผลที่ตามมา |
|---|---|
| ไม่มี bundler / npm ที่ปลายทาง | โมดูล JS ต่อกันตรงๆ ใน IIFE เดียว ไม่มี import/export |
| `file://` ส่ง HTTP Referer ไม่ได้ | ใช้ tile server แผนที่ไม่ได้เลย → วาดแผนที่เองบน canvas |
| ไม่มีที่เก็บ API key ที่ปลอดภัย | ไม่มีการเรียก API ที่ต้องใช้คีย์ใดๆ ทั้งสิ้น |

### ★ ลำดับไฟล์ JS สำคัญ

ทุกไฟล์ใน `src/js/` ถูก **ต่อกันตรงๆ** ตามลำดับใน `_order.json` แล้วห่อด้วย IIFE เดียว
ทั้งหมดจึงใช้ scope ร่วมกัน — ไม่มี `import`/`export` **โดยตั้งใจ** เพราะปลายทางไม่มี bundler

`function` hoist ข้ามไฟล์ได้ แต่ **`const`/`let` ไม่ hoist**
การสลับลำดับไฟล์อาจทำให้พังตอนรัน โดยที่ syntax ยังถูกต้อง ถ้าจะสลับต้องรันเทสต์ทุกครั้ง

ตรวจว่า build ยังตรงกับไฟล์ที่ส่งไปแล้ว:

```bash
node build.mjs --check     # เทียบทีละไบต์กับ dist เดิม
```

## ข้อมูลภายนอกที่แอปเรียก

มีอย่างเดียวคือ **Overpass API** ของ OpenStreetMap (ฟรี ไม่ต้องมีคีย์) สำหรับแผนที่และเส้นทางรถเมล์
กฎที่ต้องรักษาไว้ เขียนไว้ละเอียดใน `docs/map-howto.md` สรุปสั้นๆ:

- **POST + `Content-Type: text/plain`** เท่านั้น — เป็น CORS-safelisted จึงไม่เกิด preflight
  ใส่ header อื่นเพิ่มเมื่อไรจะพังทันทีบน `file://`
- **ต้องมี AbortController จับเวลาเอง** — `fetch` ไม่มี timeout ในตัว
- **สลับเซิร์ฟเวอร์สำรอง 3 ชั้น** ก่อนยอมแพ้: `overpass-api.de → overpass.private.coffee → overpass.osm.ch`
  (v41 ถอด `maps.mail.ru` ออกจากรายการ — คำขอแต่ละครั้งมีพิกัดจุดสื่อ Plan B จริงอยู่ในตัว
  ไม่ควรเสี่ยงให้หลุดไปเซิร์ฟเวอร์ที่ VK/Mail.ru รัสเซียดูแลตอน failover)
- โหลดเป็น 3 ช่วง แสดงผลทันทีที่แต่ละช่วงเสร็จ ช่วงหลังพังไม่ลบผลช่วงก่อน

นอกจากนี้มีแค่ Google Fonts (ถ้าโหลดไม่ได้จะ fallback เป็นฟอนต์ระบบ)

**ข้อจำกัดที่ยังเหลืออยู่ (พูดตรงๆ ไว้ตรงนี้):** ทั้ง 3 เซิร์ฟเวอร์ที่เหลือก็ยังเห็นพิกัดที่ถาม
เป็นธรรมชาติของการเรียก Overpass ทุกทาง — ทางเลือกที่เข้มกว่านี้ (ตั้ง Overpass เอง หรือพร็อกซีผ่าน
เซิร์ฟเวอร์บริษัท) ไว้พิจารณาถ้าความเสี่ยงนี้ยอมรับไม่ได้ ดู `docs/map-howto.md`

## บทเรียนที่แลกมาด้วยหลายเวอร์ชัน — อย่าทำซ้ำ

- **ห้ามตั้ง `crossOrigin` บน `<img>` ที่ใช้แสดงผล** — เปิดจาก `file://` แล้ว Origin เป็น `null` ภาพจะถูกทิ้งทั้งที่โหลดสำเร็จ
- **แก้หัวฟังก์ชันแล้วต้องอ่านท้ายฟังก์ชันเสมอ** — เคยมีโค้ดเก่าค้างท้าย ทำให้รายงานว่า error ทั้งที่สำเร็จ
- **`[]` เป็น truthy** — `if(!data)` ไม่จับกรณีอาเรย์ว่าง เคยทำให้วาดแผนที่เปล่าแล้วบอกว่าสำเร็จ
- **`[hidden]` แพ้ `display` ของคลาส** — ต้องมี `[hidden]{display:none!important}` ไม่งั้นสั่งซ่อนแล้วยังโผล่
- **ลบบล็อกโค้ดใหญ่แล้วต้อง grep หา identifier ที่เหลือ** — แล้วรันเทสต์ให้ `pageerror` เป็น 0
- **อย่าขอข้อมูลจาก Overpass แบบไม่กรอง** — `way(around:r)["highway"]` ลากทางเท้าและซอยบริการมาด้วย ในย่านกลางเมืองคือหลายพันเส้น ช้าจนหมดเวลา
- **OSM เก็บขาไป-ขากลับเป็นคนละ relation** — ถ้าไม่รวมตาม `ref` ตัวเลขสายจะพองเท่าตัว

## ข้อมูลสายรถเมล์: ระวังก่อนส่งให้ลูกค้า

- เลขสายกรุงเทพฯ อยู่ระหว่างเปลี่ยนเป็นรหัสใหม่ของกรมการขนส่งทางบก เขียนคู่กันเสมอ `77 (3-45)`
- **บล็อก "Adjacent lines" ของ transitbangkok ไม่ใช่สายที่จอดป้ายนั้น** ห้ามใช้กับงานขาย
- OSM ยังไม่ครบทุกสาย แอปจึงมีปุ่ม **ตรวจใน Google Maps** ที่ป้ายทุกป้าย
- รายละเอียดที่มาและระดับความเชื่อถือรายจุด อยู่ใน `docs/busmap-data.md`
