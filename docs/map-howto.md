# แผนที่และเส้นทางเดินรถ — วิธีที่ใช้และทำไม

## สรุปสถาปัตยกรรม
**ไม่ใช้ tile server ไม่ใช้ Leaflet ไม่ใช้ iframe**
แอปวาดแผนที่เองทุกพิกเซลลงบน `<canvas>` จากข้อมูลดิบ OpenStreetMap ที่ดึงผ่าน Overpass API

## ทำไมต้องมาทางนี้ — ไล่มาแล้วทุกทาง

| เวอร์ชัน | วิธี | ผลจริง |
|---|---|---|
| v35 | Leaflet + tile.openstreetmap.org | **403 Access blocked** — OSM บังคับ HTTP Referer แต่ `file://` ส่งไม่ได้ |
| v36 | iframe ฝังของ OSM + ตัวเปิดเซิร์ฟเวอร์ | แผนที่ขึ้น แต่วาดเส้นทางทับ iframe ไม่ได้ และผู้ใช้ไม่อยากรันตัวช่วย |
| **v37+** | **วาดเองบน canvas จากข้อมูล Overpass** | ใช้ได้ครบจากไฟล์เดียว |

จาก https://operations.osmfoundation.org/policies/tiles/ :
> "Browsers are expected to send a valid `Referer` header."
> "Traffic using generic defaults, referer-stripping, or spoofed identities may be blocked without notice."

`file://` ส่ง Referer ไม่ได้เลย และ JavaScript แก้ไม่ได้ — `<meta name="referrer">`,
`referrerPolicy` และ header `Referrer-Policy` ทำได้แค่ผ่อนคลายนโยบาย ไม่สามารถ *สร้าง*
referrer จาก origin ที่เป็น null ได้

## สิ่งที่วาดบนแผนที่
จาก Overpass: ถนน (ความหนาตามชั้น) · รางรถไฟฟ้า (เส้นประ) · แม่น้ำคูคลอง · สวนสาธารณะ ·
**เส้นทางรถเมล์แยกสีรายสาย วางขนานกันเมื่อใช้ถนนร่วมกัน** · ชื่อสถานี/ย่าน/สถานที่สำคัญ ·
ชื่อถนนวางตามแนวถนน · หมุด · วงรัศมี · เครดิต OpenStreetMap

ธีมมืดสำหรับหน้าจอ ธีมสว่างสำหรับใบนำเสนอ ใช้ฟังก์ชัน `drawMap()` ตัวเดียวกัน

## หลักการนับสาย (เปลี่ยนใน v39 — สำคัญที่สุด)
เดิมนับจาก "ถนนที่อยู่ในรัศมี" ซึ่ง **ผิดหลักสำหรับงาน OOH** เพราะรวมสายที่จอดป้ายหน้าสื่อจริง
เข้ากับสายที่แค่ขับผ่านถนนแถวนั้น

**ตอนนี้: หาป้ายรถเมล์ที่ใกล้จุดสื่อที่สุดก่อน แล้วเอาเฉพาะสายที่จอดป้ายนั้น**
ตรงกับคำถามที่ฝ่ายขายต้องตอบจริง — "สื่อตัวนี้อยู่ป้ายไหน มีรถสายอะไรจอด"

## การโหลด 3 ช่วง (v39) — เพื่อให้ขึ้นเร็ว
ยิงคำขอเดียวที่ขอทั้งแผนที่และสมาชิกทุกสายพร้อมกัน ทำให้ข้อมูลหลายเมกะไบต์
ในย่านกลางเมือง ช้าจนหมดเวลาและได้ผลลัพธ์ว่าง จึงแยกเป็น

| ช่วง | ขอ | ผล |
|---|---|---|
| A `qStops` | ป้ายรถเมล์ในรัศมีแคบ + สายที่จอดป้ายนั้น (`out tags`) | เล็กมาก รายชื่อสายขึ้นใน 1–2 วิ |
| B `qBase` | ถนน ราง น้ำ สวน ป้ายชื่อ (`out geom`) | ขนาดกลาง แผนที่วาดตามมา |
| C `qLines` | เส้นทางเฉพาะช่วงที่อยู่ในภาพ ของแต่ละสาย (`foreach`) | ระบายสีทีหลัง |

แต่ละช่วงแสดงผลทันทีที่เสร็จ **ช่วงหลังพังไม่ลบผลของช่วงก่อน**

## กฎการเรียก Overpass ที่ต้องรักษาไว้
1. **POST + `Content-Type: text/plain`** — เป็น CORS-safelisted จึงไม่เกิด preflight OPTIONS
   ซึ่งเป็นจุดที่พังบ่อยที่สุดบน `file://` · **ห้ามใส่ header อื่น**
2. **ห้ามตั้ง `credentials`** — `Access-Control-Allow-Origin: *` ไม่ match origin `null` ถ้ามี credentials
3. **ต้องมี AbortController จับเวลาเอง** — `fetch` ไม่มี timeout ในตัว
   (บั๊ก v36: เซิร์ฟเวอร์ค้าง → ปุ่มค้างที่ "กำลังถาม…" ตลอดไป) ปัจจุบัน 20 วินาทีต่อเซิร์ฟเวอร์
4. **เซิร์ฟเวอร์สำรอง 4 ชั้น**: overpass-api.de → private.coffee → maps.mail.ru → osm.ch
   (overpass-api.de มีรายงาน HTTP 406 กับ client ที่ไม่มี Referer)
5. **กดปุ่มซ้ำระหว่างรอ = ยกเลิก** ไม่ให้ผู้ใช้ต้องรอจนครบทุกเซิร์ฟเวอร์
6. **อย่าขอ `way(around:r)["highway"]` แบบไม่กรอง** — ลากทางเท้าและซอยบริการมาด้วย
   ในย่านกลางเมืองคือหลายพันเส้นที่ไม่มีทางเป็นเส้นทางรถเมล์ (ต้นเหตุความช้าใน v39)
7. **`out geom` ไม่ใช่ `out body`** สำหรับถนนที่จะวาด · `out body` บน relation
   คืนสมาชิกทั้งสายทั้งเมือง หนักเกินไป
8. **วาด polyline แยกทีละ way member** ห้ามต่อรวมเป็นเส้นเดียว ไม่งั้นได้เส้นตรงพาดข้ามเมือง
9. member ที่ role เป็น `stop`/`platform` คือป้าย ไม่ใช่เส้นทาง — ข้ามตอนวาด
10. **OSM เก็บขาไป-ขากลับเป็นคนละ relation** ต้องรวมตาม `ref` ไม่งั้นตัวเลขพองเท่าตัว
    (เคสจริง: ขึ้น 88 และ 70 สาย ทั้งที่จริงราวครึ่งเดียว)
11. **ผลลัพธ์รวมกับรายการเดิม ไม่ทับทิ้ง** เพราะ OSM ในไทยยังไม่ครบทุกสาย

## สถานะข้อมูล OSM ไทย (taginfo Geofabrik, ก.ย. 2569)
- `route=bus` = **697 relation** ทั่วประเทศ · BMTA 379, TSB 279, smart bus 103, DLT 18
- `highway=bus_stop` = **8,050 node**
- ครอบคลุมพอใช้งาน แต่ **ยังยืนยันไม่ได้** ว่า `ref` ใช้เลขเดิมหรือรหัสใหม่ และอัปเดตล่าสุดเมื่อไร
- → **อย่าใช้ OSM เป็นแหล่งเดียวสำหรับเลขสายที่ส่งให้ลูกค้า**

## ทำไมไม่ใช้ Google
- Google Maps Platform **บังคับ API key + บิลลิ่ง** ทุก endpoint ที่ให้ข้อมูลขนส่งสาธารณะ
  ขัดกับการตัดสินใจถอด API key ออกเพื่อความปลอดภัย
- ไม่มี API ของ Google ที่ให้ข้อมูลสายรถเมล์แบบไม่ต้องมีคีย์
- ดึงจากหน้าเว็บ Google Maps ตรงๆ ถูก CORS บล็อกและผิด ToS
- **ทางออกที่ใส่แทน:** ปุ่ม "ตรวจใน Google Maps" ที่ป้ายทุกป้าย เปิดพิกัดป้ายนั้นใน Google ทันที
